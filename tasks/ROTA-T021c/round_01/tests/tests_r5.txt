REMAINING BLOCKER — an already scheduled background error is attributed to a
later unrelated click

TRACE

The accepted brief §3.2 states both that delayed correlation is best-effort and
that an ambiguous error must NEVER resolve another, unrelated click; it must
remain without action_id instead.

OWNERSHIP

- tracking.ts owns pendingActionId and its clearing window.
- globalHandlers.ts reads that value into exported global-error events and
  resolves the corresponding action.

INDEPENDENT REPRODUCTION

Two equivalent real-browser cases were parameterized:

1. a background setTimeout that will throw window.error is scheduled;
2. a separate inert control is clicked before that queued task executes;
3. the same case is repeated for unhandledrejection.

The background failure was scheduled before the click, so the click cannot be
its cause. On the audited SHA, both error kinds receive the inert click's
action_id. resolveAction() then suppresses ACTION_STALLED for that inert click.

Observed in both cases:

- expected error action_id: null;
- actual error action_id: the unrelated inert click ID;
- expected ACTION_STALLED for the inert click: present;
- actual ACTION_STALLED: absent.

This is not the withdrawn requirement to recover the original cause of
arbitrarily delayed work. The test only enforces the retained fail-safe rule:
when causality is not established, do not claim one and do not resolve another
action.

CAUSE

setPendingActionId() now retains the most recent click across two chained
macrotasks so a direct Promise.reject() can reach unhandledrejection. During
that interval globalHandlers.ts treats temporal proximity as causality. A
previously queued, unrelated task can execute inside the same interval.

The implementation comment saying the extra queue turn is shorter than any
subsequent unrelated task is disproved by the reproducer: the unrelated task
was queued first and executes before the clearing tasks.

REQUIRED BEHAVIORAL CORRECTION

- Global errors and rejections must always remain recorded.
- A global error may carry an action_id and resolve an action only when its
  provenance to that action is positively established under the accepted
  contract.
- Mere occurrence inside a recent-click timer window is not sufficient.
- Otherwise action_id must be null and the unrelated click must remain
  unresolved, allowing ACTION_STALLED to be emitted.
- Preserve the passing direct render/error export cases and the round-4
  delayed-error case to the extent required by the accepted brief; do not
  restore global timer/Promise/microtask monkey-patching.
- Keep both round-5 cases as regression coverage for the shared false-causality
  class.
