ACCEPTED R4 CONTRACT NARROWING

The owner/Codex ruling after round 3 is accepted and used as PRODUCT_TRUTH:

- every click is recorded;
- req(), navigation and direct render/global errors are correlated when the
  originating action ID is reliably available;
- arbitrarily delayed errors are recorded but their action correlation is
  best-effort;
- an ambiguous error remains uncorrelated and must not resolve another click;
- ACTION_STALLED means "no confirmed reaction", not proof that no reaction
  occurred;
- no global monkey-patching of timer/Promise/microtask scheduling.

The withdrawn R3 expectation of perfect correlation for arbitrary async work
is not retested and is not a defect under this narrowed contract.

REPRODUCED EQUIVALENCE CLASS

Three real-browser cases were executed independently:

1. direct click-triggered RENDER_ERROR;
2. direct click-triggered UNHANDLED_ERROR;
3. direct click-triggered UNHANDLED_REJECTION.

In every case the originating CLICK_RECEIVED has a valid action_id and the code
uses that ID internally to suppress ACTION_STALLED. However, the corresponding
error event exported in the diagnostic buffer has action_id=undefined because
RenderErrorEvent, UnhandledErrorEvent and UnhandledRejectionEvent contain no
action_id field and the handlers never write it.

The downloaded report therefore cannot show the reliable relationship that the
implementation already established internally.

REQUIRED CORRECTION

- Add action_id: string | null to all three exported error event shapes.
- Read the pending ID once per error, put that exact value in the event and use
  the same value for resolveAction().
- Direct error cases must export the click's ID.
- Delayed/ambiguous error cases must export null and resolve no action.
- Keep all four R4 browser cases as the bounded regression family.
