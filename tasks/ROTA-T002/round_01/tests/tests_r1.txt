CZĘŚĆ C — ARCHITECTURE PROPOSALS (NIE WPŁYWAJĄ NA FAIL)

C1. Immutable snapshot

Obecne zachowanie: mutable dataclass z mutable lists.

Propozycja: po decyzji właściciela rozważyć `@dataclass(frozen=True)` oraz tuple dla kolekcji snapshotu. Jeżeli wymagana jest wyłącznie shallow immutability, zachować Sequence/list semantics i udokumentować poziom.

Korzyść: PlanningEngine nie może przypadkowo zmienić wejścia podczas planowania.
Tradeoff: tuple utrudnia inkrementalne składanie; assembler musi budować mutable buffers i zamrażać finalny snapshot.

C2. Jawne rule sets

Obecne zachowanie: jedna lista resolved rules, brak unresolved display data.

Propozycja: osobne `resolved_site_rules` i `unresolved_site_rules` albo value object z dwoma nazwanymi zbiorami.

Korzyść: STATE-01 jest widoczne w typie i trudniejsze do przypadkowego naruszenia.
Tradeoff: szerszy publiczny kontrakt PlanningState.

C3. Jawny ScheduleVersion snapshot

Obecne zachowanie: id + assignments.

Propozycja: trzy kolekcje `shift_demands`, `existing_assignments`, `deviations` lub osobny immutable snapshot current version.

Korzyść: PlanningEngine dostaje kompletny, rekonstruowalny kontekst bez persistence reads.
Tradeoff: duplikacja części danych ScheduleVersion albo kolejny value object.

C4. Other-site context wrapper

Obecne zachowanie: brak site metadata dla external assignments.

Propozycja: wrapper zawierający site_id/schedule_version_id/Assignment albo mapa site_id → tuple[Assignment, ...].

Korzyść: globalne per-employee REST/LOAD są audytowalne.
Tradeoff: dodatkowy typ; nie należy go dodawać bez decyzji właściciela.

C5. Acceptance derived from current contract

Obecne zachowanie: acceptance sprawdza pola/import/ruff/rozmiar, ale nie objective immutability ani Frozen completeness.

Propozycja: po korekcie Task Contract dodać introspection wszystkich required fields, próbę reassignment, próbę mutacji reprezentatywnej kolekcji oraz negatywny check, że unresolved rules nie trafiają do executable set.

Korzyść: testuje klasy błędów, nie tylko import observed instance.
Tradeoff: oczekiwania immutability mogą zostać dodane dopiero po decyzji B1.
