ARCHITECTURE_PROPOSAL (nonblocking, once only)

Current behavior: frontend writes may carry technical decision IDs, while this
new action always targets the one current decision for its exact Site/month.
Proposal: let the backend command resolve and lock that current decision itself
instead of asking the browser to send an identifier. Benefit: smaller UI payload,
no technical ID exposure and no wrong-month selection. Tradeoff: the command is
intentionally restricted to the current decision and cannot answer a historical
one — which matches the frozen T061 contract.
