WYMAGA_DECYZJI C-R3-1 — KONTRAKTOWA ODWRACALNOŚĆ NIE ISTNIEJE DLA SITE I COORDINATOR

Ślad kontraktu:

- `brief.md`, sekcja „Samozablokowanie jest oczekiwanym, odwracalnym
  zachowaniem”, wymienia równorzędnie
  `update_association(active=False)`, `update_coordinator(active=False)` i
  `update_site(active=False)`;
- ta sama sekcja stwierdza, że po każdym takim zapisie nie ma aktywnej asocjacji
  i bootstrap może wznowić kontekst;
- ACCEPTANCE wymaga, aby wszystkie operacje zmiany aktywności były odwracalne;
- jednocześnie bootstrap ma nadal odmawiać, dopóki Association jest aktywna.

Rzeczywisty właściciel zachowania:

- `context.require_active_coordinator_context` wymaga aktywnego Coordinator,
  aktywnego Site i aktywnej Association;
- `bootstrap._has_active_association` sprawdza wyłącznie
  `CoordinatorSiteAssociation.active`;
- `bootstrap_or_resume_coordinator_context` wykonuje ten test przed jakimkolwiek
  supplied write i przy aktywnej Association podnosi
  `CoordinatorContextAlreadyActive`.

Niezależne odtworzenie przez publiczne API dało pełną klasę:

| Dezaktywowany rekord | Następny durable input | Bootstrap resume |
| --- | --- | --- |
| Association | `InvalidCoordinatorContext` | działa |
| Coordinator | `InvalidCoordinatorContext` | `CoordinatorContextAlreadyActive` |
| Site | `InvalidCoordinatorContext` | `CoordinatorContextAlreadyActive` |

Dwa ostatnie przypadki pozostawiają aktywną Association, więc zdanie kontraktu
„skoro nie ma już aktywnej asocjacji” jest dla nich fałszywe. Po odrzuceniu
bootstrapu guard nie pozwala również zwykłym wrapperom ponownie aktywować Site
ani Coordinator. Test 6 pokrywa tylko wariant Association i dlatego nie wykrywa
obu siblingów tej samej klasy.

To nie jest miejsce na wybór nowej architektury przez audytora. Zamknięcie
wymaga pisemnego rozstrzygnięcia właściciela, które ujednolici wymaganie
odwracalności, ochronę aktywnego bootstrapu i TASK_SCOPE. Dopiero po tej decyzji
macierz musi objąć wszystkie trzy równoległe ścieżki, zgodnie z ostatecznym
kontraktem.

Brief przeszedł już dwie rundy audytu kontraktu. Zgodnie z granicą roli nie
zalecam kolejnych iteracji językowych prowadzących do preferowanej przeze mnie
architektury; dalsza implementacja tego punktu powinna się zatrzymać do decyzji
właściciela/architekta. Wniosek SECTION_CHECK 2 z tests_r2 o odwracalności
wszystkich wariantów zostaje niniejszym skorygowany na podstawie wykonanego
reproducera.
