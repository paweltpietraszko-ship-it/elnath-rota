FINDING R1-2 — MEDIUM — JSON BOUNDARY MILCZĄCO ZMIENIA LUB AKCEPTUJE DANE SPOZA JSON

Ślad kontraktowy:
- tasks/ROTA-T005/brief.md:152–168: JSON jest wyłącznie formatem persistence;
  boundary przyjmuje reprezentację JSON-compatible i odczytuje ją bez zmiany
  znaczenia;
- acceptance #20: T005 ma zachować tę granicę bez zamrażania domenowego typu;
- deklaracja implementacji mówi o odrzuceniu danych nie-JSON.

Macierz siblingów:
- `{1: "x"}` zapisuje się, lecz odczytuje jako `{"1": "x"}`;
- `{"tuple": (1, 2)}` zapisuje się, lecz odczytuje jako
  `{"tuple": [1, 2]}`;
- NaN jest przyjmowane przez json.dumps i po round-trip nie jest nawet równe
  własnej wartości wejściowej;
- Infinity jest zapisywane jako niestandardowy token JSON zamiast zostać
  odrzucone.

Przyczyna:
- site_rule_repository._dump_parameters() wywołuje json.dumps(value) z
  ustawieniami domyślnymi;
- domyślny encoder Pythona konwertuje klucze niebędące tekstem i tuple oraz
  dopuszcza NaN/Infinity;
- obsłużony TypeError dla object() pokrywa tylko jeden przypadek nie-JSON,
  nie całą klasę granicy.

Dopuszczalne zachowanie wynikające z kontraktu:
- przyjąć wyłącznie rzeczywiście JSON-compatible strukturę i zachować ją
  semantycznie bez zmian;
- albo odrzucić wejście przed zapisem typowanym błędem.

Nie wymaga to definiowania przyszłego RuleParameters ani katalogu rule_kind.
Dotyczy wyłącznie poprawności zadeklarowanego adaptera persistence.
