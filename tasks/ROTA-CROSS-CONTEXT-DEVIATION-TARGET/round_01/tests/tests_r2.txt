Why the verdict is stopped
--------------------------
The brief and the preimplementation audit treated a cross-context
MalformedScheduleSnapshot as a currently reachable product crash. Independent
inspection on the exact baseline shows that this premise became stale before
the Task was written:

- ROTA-T036 maps REST-01 and WEEKLY-REST-01 to the affected Employee, not to
  either diagnostic Assignment id;
- THIRD-CONSECUTIVE-SHIFT-01 collects ids only from the target version's
  `assignments` argument; boundary Assignments contribute dates, not ids;
- these are all currently shipped sources mapped to DeviationCategory.LAW.

Therefore no current normal validator -> deviation mapping -> persistence path
produces a LAW Deviation whose target is a cross-context Assignment. The new
branch is defensive/forward-looking behavior, not a fix for a currently
reproducible crash.
